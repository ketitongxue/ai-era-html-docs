定义用户基本接口

我们从用户模块开始起步。

对于一个用户模块来说，最先要设计的接口就是：注册和登录。

而后要考虑提供：编辑和查看用户信息。

注意，我的个人偏好是在研发的时候，从前端往后端。即先定义 Web 接口，再去考虑后面的数据库设计之类的东西。这种偏好是早期和前端对接的时候养成的，因为以前先定义数据库，经常遇到前端需要加字段的问题，所以后面我索性就都先定义前端了。

Handler 的用途

这里，我直接定义了一个 UserHandler，然后将所有和用户有关的路由都定义在了这个 Handler 上。

同时，也定义了一个 RegisterRoutes 的方法，用来注册路由。

你可以注意到，我用定义在 UserHandler 上的方法来作为对应路由的处理逻辑。

在简单的应用里面，这是一种不错的 Web 代码组织方式，比如说我后续可以有 ArticleController 啥的。

集中注册 VS 分散注册

UserHandler 上的 RegisterRoutes 是一种分散注册路由的做法。还有一种集中式的做法，比如说在 main 函数里面将所有的路由都注册好。

集中注册优点：打开你就能看到全部路由。缺点：路由太多的时候，你找起来很费劲。

分散注册优点：比较有条理。缺点：找路由的时候不好找。

func main() {
    server := gin.Default()
    
    u := &web.UserHandler{}
    server.POST("/users/signup", u.SignUp)
    server.POST("/users/login", u.Login)
    server.POST("/users/edit", u.Edit)
    server.GET("/users/profile", u.Profile)
    
    // 这里还有别的路由
    
    server.Run(":8080")
}

func main() {
    server := gin.Default()
    
    u := &web.UserHandler{}
    u.RegisterRoutes(server)
    
    // 这里还有别的路由
    server.Run(":8080")
}

用分组路由来简化注册

你可以注意到，就是我们所有的路由都有 /users 这个前缀，要是手一抖就有可能写错，这时候可以考虑使用 Gin 的分组路由功能。

分组功能你可以理解为一种便利手段，就是为了方便你组织代码而引入的一种功能。

注册页面：后端怎么处理？

类似于把大象放进冰箱，后端处理也就是三步骤：

  • 接收请求并校验
  • 调用业务逻辑处理请求
  • 根据业务逻辑处理结果返回响应

于是问题变成了：怎么在后端接收这个 JSON 数据？

接收请求数据：接收请求结构体

一般来说，我们都是定义一个结构体来接受数据。

这里我们使用了方法内部类 SignUpReq 来接收数据。

优点：除了这个 SignUp 方法能够使用 SignUpReq，其它方法都用不了。

你也可以考虑定义在外面，跟习惯、公司偏好相关。

我建议优先使用内部类。

接收请求数据：Bind 方法

Bind 方法是 Gin 里面最常用的用于接收请求的方法。

Bind 方法会根据 HTTP 请求的 Content-Type 来决定怎么处理。

比如我们的请求是 JSON 格式，Content-Type 是 application/json，那么 Gin 就会使用 JSON 来反序列化。

如果 Bind 方法发现输入有问题，它就会直接返回一个错误响应到前端。

校验请求

实际上，校验什么字段、怎么校验，理论上来说都应该是你们公司的产品经理来告诉你的。

在我们这个注册的业务里面，校验分成两块：

  • 邮箱需要符合一定的格式：也就是账号这里，必须是一个合法的邮箱。
  • 密码和确认密码需要相等：这是为了确保用户没有输错。
  • 密码需要符合一定的规律：要求用户输入的密码必须不少于八位，必须要包含数字、特殊字符。

密码强度说重要，确实重要，但也没有以前那么重要了。现在更加强调的是通过二次验证这种机制来保证登录安全性。

有一个问题：能不能让前端校验？

答案：你不能仅仅让前端校验，比如 postman 直接请求，前端防不住。

加密？不如使用 https 传输。

校验请求：正则表达式

校验请求，用正则表达式。

正则表达式是一种用于匹配和操作文本的强大工具，它是由一系列字符和特殊字符组成的模式，用于描述要匹配的文本模式。

正则表达式可以在文本中查找、替换、提取和验证特定的模式。我的建议是不用学，要用的时候直接搜别人写好的。我也只会最简单的。

如果你的校验规则很复杂，你就多来几个校验表达式进行多次校验。

校验的时候，只需要使用 regexp 包中的 Match 方法就可以。

校验请求：预编译正则表达式

我们可以预编译正则表达式来提高校验速度。

校验请求：Go 正则表达式不支持部分语法

前面我们用的是官方自带的，但是 Go 自带的正则表达式不支持一些语法，比如说我这里想要用的表达式：

^(?=.*[A-Za-z])(?=.*\d)(?=.[*$@$**!%*#?&])[A-Za-z\d$@$!%*#?&]{8,}$

类似于 ?=. 这种就不支持。

所以我们换用另外一个开源的正则表达式匹配库：github.com/dlclark/regexp2。

import (
    regexp "github.com/dlclark/regexp2"
)

emailExp := regexp.MustCompile(emailRegexPattern, regexp.None)
passwordExp := regexp.MustCompile(passwordRegexPattern, regexp.None)
